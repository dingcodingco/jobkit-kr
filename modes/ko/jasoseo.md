# 모드: jasoseo -- 자기소개서 문항 답변

한국 채용의 자기소개서는 서구권 커버레터와 다른 문서다. 편지 한 장이 아니라
**문항이 여러 개 있고 각 문항에 글자수 상한이 걸린 양식**이고, 상당수 기업이
이걸로 1차 서류 합격을 가른다. `modes/cover.md`(커버레터)를 한국 자소서에
그대로 쓰면 문항 구조를 못 맞춘다. 그래서 이 모드가 따로 있다.

`_shared.md`의 규칙이 전부 그대로 적용된다. 특히 다음 두 가지를 먼저 읽는다.

- **없는 경력·수치·기간을 만들지 않는다.** `cv.md`와 `article-digest.md`에
  없는 내용은 쓰지 않고, 필요하면 후보자에게 묻는다.
- **제출은 후보자가 한다.** 이 모드는 초안까지만 만든다.

## 입력

| 파일 | 용도 |
|------|------|
| `cv.md` | 경력·프로젝트·수치의 유일한 출처 |
| `article-digest.md` (있다면) | 상세 proof point |
| `config/profile.yml` | 신원, 목표 역할, 전환 narrative |
| 공고 원문 | 문항, 글자수, 회사가 쓴 표현 |

문항과 글자수는 **후보자가 실제 지원 폼에서 복사해온 것**을 쓴다. 추측해서
만든 문항으로 초안을 쓰면 글자수가 안 맞아 통째로 다시 써야 한다. 문항을 못
받았으면 먼저 요청한다.

## Step 0 -- 글자수 규칙 확인

한국 지원 폼의 글자수는 기업마다 세는 법이 다르다. 이걸 먼저 확정하지 않으면
초안이 폼에 안 들어간다.

- **공백 포함 / 공백 제외** — 같은 "1000자"도 실제 분량이 꽤 달라진다
- **줄바꿈이 글자로 세어지는지** — 세는 폼에서 단락을 많이 나누면 손해다
- **최소 글자수** — "500자 이상"이 걸린 문항은 미달하면 제출 자체가 안 된다

확인이 안 되면 **공백 포함 기준으로 상한의 90~95%**를 목표로 잡는다. 넘치는
것보다 조금 모자란 게 안전하다.

각 문항 초안 끝에 실제 글자수를 적는다. 이렇게:

```
(공백 포함 948자 / 상한 1000자)
```

## Step 1 -- 문항 유형 분류

문항을 아래 유형으로 나눈다. 유형에 따라 근거로 쓸 재료가 달라진다.

| 유형 | 전형적인 문구 | 주로 쓰는 재료 |
|------|---------------|----------------|
| **지원동기** | "지원한 이유", "왜 우리 회사인가" | 공고의 문제 + cv.md의 관련 경험 |
| **직무역량** | "직무 관련 경험", "본인의 강점" | cv.md의 프로젝트와 수치 |
| **문제해결** | "어려움을 극복한 경험", "갈등 상황" | cv.md의 구체적 사건 하나 |
| **성장과정** | "성장과정", "가치관 형성" | 후보자 본인만 아는 내용 — 반드시 물어본다 |
| **입사 후 포부** | "입사 후 계획", "3년 뒤 모습" | 공고의 업무 범위 + 후보자의 방향 |
| **자유기술** | "자유롭게 기술", "추가로 하고 싶은 말" | 문항으로 못 담은 강점 |

**성장과정·가치관 유형은 초안을 먼저 쓰지 않는다.** 이 유형은 후보자의 개인사가
재료인데 `cv.md`에 없다. 지어내면 면접에서 바로 무너진다. 후보자에게 질문
3~4개를 던져 재료를 받은 뒤에 쓴다.

## Step 2 -- 문항별 초안

각 문항을 아래 형태로 쓴다.

**두괄식.** 첫 문장에 결론을 놓는다. 서류를 보는 사람은 한 문항에 20초를 쓴다.
"저는 어릴 때부터"로 시작하는 문항은 첫 문장이 버려진다.

**한 문항 = 한 사례.** 1000자에 프로젝트를 셋 넣으면 셋 다 얕아진다. 하나를
골라 상황·행동·결과를 다 적는 쪽이 읽힌다.

**숫자는 `cv.md`에 있는 것만.** 숫자 옆에 출처를 주석으로 남긴다. 후보자가
검토할 때 대조할 수 있어야 한다.

```
매출 데이터 집계 시간을 주 8시간에서 40분으로 줄였습니다.
<!-- 출처: cv.md "데이터팀 / 2024" 항목 -->
```

**공고의 표현을 가져다 쓴다.** 공고가 "데이터 기반 의사결정"이라고 썼으면
"데이터로 판단하는"이 아니라 그 표현을 그대로 쓴다. 키워드 필터를 돌리는
회사가 있고, 아니어도 읽는 사람이 자기 문장을 알아본다. 단 **표현만 가져오고
없는 경험을 만들지 않는다.**

**회사 이름을 한 번은 구체적으로 쓴다.** 어느 회사에 내도 되는 자소서는 티가
난다. 공고나 회사 페이지에서 확인한 사실 하나를 박는다.

## Step 3 -- 검토 블록

초안 뒤에 아래를 붙인다. 후보자가 제출 전에 직접 확인할 목록이다.

```markdown
## 제출 전 확인

- [ ] 글자수: 문항별 실제 수치와 상한 (공백 포함/제외 기준 명시)
- [ ] cv.md에 없는 경력·수치·기간이 들어가지 않았는지
- [ ] 회사명·직무명이 이 공고의 것과 맞는지 (다른 회사 이름이 남아 있지 않은지)
- [ ] 성장과정·가치관 문항이 본인이 준 재료로만 쓰였는지
- [ ] 면접에서 이 내용으로 10분간 질문받아도 답할 수 있는지
```

마지막 항목이 실질적인 기준이다. 자소서는 면접 질문지가 된다. 답할 수 없는
문장은 빼는 게 낫다.

## 하지 않는 것

- 지원 폼에 입력하거나 제출하지 않는다. 초안 파일까지만 만든다.
- 없는 수상·자격증·학력·경력을 만들지 않는다.
- 다른 사람의 자소서 문장을 가져오지 않는다.
- 합격을 보장한다고 말하지 않는다. 서류 통과율을 예측하지 않는다.

## 출력

`output/jasoseo/{회사}_{직무}_{YYYY-MM-DD}.md` 한 파일에 문항별 초안과 검토
블록을 담는다. tracker에는 지원 자료 링크로 이 경로를 남긴다.
